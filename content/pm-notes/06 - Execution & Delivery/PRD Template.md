# PRD Template

## Definition
A reusable, fill-in-the-blank structure for writing a Product Requirements Document. Where "AI PRD" describes the *concept* of adapting a PRD for AI-specific constraints, this is the actual skeleton to copy into a new doc: **Problem Statement**, **Goals & Non-Goals**, **User Stories**, **Requirements** (functional and non-functional), **Success Metrics**, and **Open Questions**.

## How to Apply It
1. **Problem Statement**: One paragraph on the user pain point and why it matters now.
2. **Goals & Non-Goals**: List what this release will and explicitly will *not* address, to bound scope.
3. **User Stories**: Write the core flows as "As a [user], I want to [action], so that [outcome]."
4. **Requirements**: Split into functional (what it does) and non-functional (latency, accuracy, security constraints).
5. **Success Metrics**: Define the specific metric(s) and target that will determine if this shipped successfully.
6. **Open Questions**: List unresolved decisions so reviewers know what still needs input, rather than assuming silence means agreement.
